SecretSpec 0.18 is now available.

A declarative secrets workflow needs more than a way to read values. It needs to cover the full lifecycle while keeping the application’s committed requirements separate from each environment’s stored secrets.

SecretSpec can now add declarations, delete stored values, and safely move values between providers:

• `secretspec add` updates the selected profile while preserving the manifest’s comments and formatting
• `secretspec delete` removes a value without removing the application’s declaration
• `secretspec import --delete-source` verifies the destination before deleting the source and retains it when values conflict
• `secretspec init --from` discovers declarations from age files, AWS Parameter Store hierarchies, and Bitwarden collections without writing values to the manifest

0.18 also adds four providers, bringing the total to 24:

• Bitwarden Password Manager
• Keeper Secrets Manager
• AWS Systems Manager Parameter Store
• Dashlane

Swift joins the SDK family on macOS through a checksummed XCFramework containing the shared Rust resolver. Applications get the same profiles, scopes, providers, references, typed failures, preflight reports, and temporary-file behavior as the CLI and other language SDKs.

Vault and OpenBao also gain custom AppRole and JWT mount paths, support for AppRoles without SecretID binding, and server-default JWT roles.

And SecretSpec has a new logo.
