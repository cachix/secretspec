The Elixir SDK (`secretspec`, 0.22+) is a pure Elixir client for the `secretspec.resolver/1` IPC protocol. It requires a compatible `secretspec` executable (0.21+) and launches `secretspec serve` directly, without a shell, NIF, native archive, or Rust code in the Hex package.

## Install

```elixir
defp deps do
  [{:secretspec, "~> 0.22"}]
end
```

The package requires Elixir 1.19 or later. Run `mix deps.get` to fetch it.
Install the [SecretSpec CLI](/quick-start/) separately and make `secretspec`
available on `PATH`, or set `executable:` as described below.

## Caller context

Pass `purpose:` on every `Session.get/3` call. It must contain non-empty
`consumer` and `operation` strings; `host` and `path` are optional attribution
fields:

```elixir
SecretSpec.Session.get(session, "DATABASE_URL",
  representation: :value,
  purpose: %{consumer: "my_app", operation: "connect", host: "db.example.com"}
)
```

Set the session's `reason:` to explain why secrets are being accessed. Caller
attribution does not satisfy a project's `require_reason` policy. Keep secret
values out of both the purpose metadata and the reason.

## Scopes

Pass `scope: "api"` when opening the session to limit access to a named
`[scopes.api]` subset:

```toml
[project]
name = "my_app"
revision = "1.0"

[profiles.default]
DATABASE_URL = { description = "Database URL" }
API_KEY = { description = "API key" }
DEPLOY_TOKEN = { description = "Deployment token" }

[scopes.api]
secrets = ["DATABASE_URL", "API_KEY"]
```

## Typed access

Successful results use the `%SecretSpec.Secret{}` struct. Pattern-match on
`value` for inline secrets or `path` and `lease_id` for file secrets, as shown
in the quick-start and file examples. `representation: :value` or `:path`
makes the expected result explicit; the default, `:auto`, follows the secret's
declaration. The Elixir SDK resolves individual names and does not expose the
whole-profile field map used by other SDKs' code-generation examples.

## Sessions

A session fixes the manifest, profile, scope, provider override, and reason for
its lifetime. For multiple requests, keep a session open and close it after
the last consumer finishes:

```elixir
{:ok, session} =
  SecretSpec.Session.start_link(
    manifest: "secretspec.toml",
    profile: "production",
    provider: "keyring://",
    reason: "start application"
  )

try do
  SecretSpec.Session.get(session, "DATABASE_URL",
    representation: :value,
    timeout: 5_000,
    purpose: %{consumer: "my_app", operation: "connect"}
  )
after
  SecretSpec.Session.close(session)
end
```

`timeout:` is a per-request deadline in milliseconds, defaulting to 30,000.
Requests that reach their deadline return an error with
`kind: "deadline_exceeded"`. `start_link/1` links the session to the calling
process; `with_session/2` also arranges cleanup when its owner exits.

## Results

- `{:ok, %SecretSpec.Secret{}}`
- `{:missing, required}`
- `:undeclared`
- `{:error, %SecretSpec.Error{}}`

`%SecretSpec.Error{}` carries `kind`, `message`, and `data`. Match on `kind`
for error handling. See the [resolver protocol](/reference/resolver-protocol/)
for result semantics and error categories.

## Executable discovery

The SDK finds `secretspec` through `PATH`. Point a session at a particular
installation with an absolute `executable:` path:

```elixir
{:ok, session} =
  SecretSpec.Session.start_link(
    executable: "/opt/secretspec/bin/secretspec",
    manifest: "secretspec.toml"
  )
```

The SDK starts the executable with `serve` and negotiates
`secretspec.resolver/1`. Include the CLI and any provider executables in your
deployment environment. Whole-profile resolution and value-free reports are
not exposed by the Elixir SDK; use [`secretspec check`](/reference/cli/#check)
for preflight checks.
