SecretSpec 0.15 is now available.

The feature I’m most excited about solves an awkward problem in secrets management: where do you keep the secret needed to open your secret store?

SecretSpec providers can now receive their credentials from another provider. A Bitwarden token can live in the OS keyring. Vault AppRole credentials can come from 1Password. Azure service principal credentials can be stored locally instead of exported into every application environment.

SecretSpec resolves that credential, passes it directly to the destination provider in memory, and keeps it out of the process started by secretspec run.

It’s a deliberately bounded chain with one hop. That makes the bootstrap path useful without making it mysterious. Credentials still get semantic validation, caching, and audit events that never contain their values.

SecretSpec 0.15 also brings:

• Azure Key Vault and Gopass providers
• A new PHP SDK
• Secret export for shells, dotenv, JSON, and GitHub Actions
• AWS Secrets Manager creation guardrails
• More reliable lazy provider fallback chains
• Profile, validation, and Linux compatibility fixes

This release makes SecretSpec work across more environments while removing another reason to pass sensitive credentials through environment variables.
